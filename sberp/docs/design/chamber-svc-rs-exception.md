ERP와 현황판이 같은 규칙으로 검사해야 한쪽에서 통과한 기록이 다른 쪽에서 막히지 않습니다.

## 1. 확정 규칙

| # | 규칙 |
|---|---|
| R-1 | 시험원 1명은 한 번에 시험 1건만 진행한다 (기획 V-1). |
| R-2 | **예외**: RS 시험끼리는 한 시험원이 동시에 진행할 수 있다. |
| R-3 | RS 시험 중인 사람은 RS가 아닌 시험을 시작할 수 없다. |
| R-4 | RS가 아닌 시험 중인 사람은 RS 시험을 시작할 수 없다. |
| R-5 | RE (10m)에서 RS (#3실) 항목으로 시작한 시험도 RS 시험이다. |
| R-6 | 중복 단위는 **시험번호 + 시험항목**이다. 같은 시험번호라도 시험항목이 다르면 동시에 진행할 수 있다. 같은 시험번호의 같은 항목은 한 곳에서만 진행한다. 예: 같은 번호의 RS를 RS #2·RS #4에서 동시에 진행할 수는 없다 (RS는 항목 1개). 시험원 조건은 따로 R-1~R-5로 본다. |
| R-7 | 기록 수정(시작·종료 시각, 시험원 변경)에서도 R-1~R-5를 똑같이 검사한다. |
| R-8 | 시험원 = 로그인 아이디. ERP 측정 행은 `RAW_ENV_TB.MEM_ID`([시작]을 누른 사람), 현황판 기록은 `CHAMBER_ETC_USE_TB.MEM_ID`(시험원). 입회 시험(`MEM_ID` 없음)은 검사 대상이 아니다. |

### RS 판단 기준 (ERP와 같아야 함)

| 기록 | RS로 보는 조건 |
|---|---|
| 측정 행 `RAW_ENV_TB` | `MET_KEY = 'RS'` |
| 현황판 기록 `CHAMBER_ETC_USE_TB` | `ZONE_SEQ` 구역에 `CHAMBER_ZONE_MET_TB.MET_KEY = 'RS'` 매핑이 있음 |

- 지금 데이터로는 RS #2 · RS #3 · RS #4 · RE (10m)/RS (#3실) 구역이 해당됩니다.
- 시험번호 없이 쓰는 경우(장비 점검 등)라도 RS 구역이면 RS로 봅니다.
- 시험장 전체 점유(`WHOLE_YN=1`)는 그 챔버의 첫 구역으로 판단합니다. 따라서 RS #2 전체 점유는 RS이고, RE (10m) 전체 점유는 RS가 아닙니다.
- 이름(`'RS #2'` 등)을 코드에 직접 쓰지 않고 매핑 테이블로 판단합니다. 나중에 RS 구역이 늘어도 매핑만 추가하면 됩니다.

SQL 조각 예시 (ERP `rsZoneYn`과 같음):

```sql
-- 측정 행
IF(e.MET_KEY = 'RS', 1, 0) AS RS_YN
-- 현황판 기록
IF(EXISTS (SELECT 1 FROM CHAMBER_ZONE_MET_TB rm WHERE rm.ZONE_SEQ = x.ZONE_SEQ AND rm.MET_KEY = 'RS'), 1, 0) AS RS_YN
```

새로 시작(또는 수정)하는 기록이 RS이면 **상대 `RS_YN = 1`인 건을 검사 대상에서 뺍니다.** 새 기록이 RS가 아니면 지금처럼 전부 검사합니다.

## 2. 수정할 곳

### 2-1. 사용 시작 — `app/db.py` `start_etc_use` (1인 1시험 블록, 503줄 근처)

- 지금: `ACTIVE_UNION`에서 `u.MEM_ID = %s`인 진행 중 건이 하나라도 있으면 거부합니다.
- 변경:
  1. 시작할 구역이 RS인지 판단합니다. 전체 점유면 바뀐 첫 구역 `zone_seq` 기준입니다.
  2. `ACTIVE_UNION` 두 SELECT에 `RS_YN` 열을 추가합니다. 위 SQL 조각을 쓰고, 다른 쿼리가 `u.*`로 쓰므로 양쪽에 모두 넣어야 합니다.
  3. RS로 시작하는 경우 `AND u.RS_YN = 0` 조건을 추가합니다.
- 거부 문구는 그대로 둬도 됩니다. RS ↔ 비RS로 막힌 경우는 "RS 시험과 다른 시험은 동시에 할 수 없습니다"처럼 구분해 주면 더 좋습니다.

### 2-2. 기록 수정 — `app/db.py` `edit_etc_use` (시험원 겹침 블록, 336줄 근처)

- 지금: 같은 `MEM_ID`의 측정 행과 현황판 기록 가운데 시간이 겹치는 건이 있으면 거부합니다. 시험장 겹침 검사(V-3)는 손대지 않습니다.
- 변경: 2-1과 같은 RS 예외를 적용합니다. 수정하는 기록의 구역(`row["ZONE_SEQ"]`)이 RS이면 상대 `RS_YN = 1`인 건을 제외합니다.
- 같이 확인할 점: 진행 중인 기록을 수정하면 `end_dt`가 `None`이라 `COALESCE(%s, '9999-12-31')`로 끝이 없는 것으로 봅니다. 이 처리는 맞으니 그대로 둡니다.

### 2-3. 시험원 고르기 목록 — `app/db.py` `fetch_members` (668줄 근처) + `/api/members` + 화면

- 지금: 진행 중인 건이 있는 사람은 `busy`에 시험장 이름이 붙고, 화면에서 고를 수 없습니다.
- 변경: 진행 중인 건이 **모두 RS인 사람**은 RS 구역을 시작할 때 고를 수 있어야 합니다.
  - `fetch_members`가 사람별로 `BUSY`(시험장 이름)와 함께 `BUSY_RS_ONLY`(진행 중 건이 전부 RS이면 1)를 돌려줍니다. 예: `MIN(u.RS_YN)`.
  - `/api/members` 응답에 `busyRsOnly`를 추가합니다.
  - 시작 팝업(`index.html`): 시작하는 항목·구역이 RS이고 `busyRsOnly`이면 막지 않고, "RS #2 시험 중 (RS 동시 진행 가능)"처럼 안내만 보여 줍니다.
  - 화면이 구역의 RS 여부를 알 수 있게 `/api/status` 구역에 `mets`(시험방법 매핑)·`rsYn`, `/api/zones`에 `rsYn`을 추가합니다.
  - 시험원 로그인(본인 고정)도 같습니다. 본인이 RS 시험 중이면 RS 구역의 [사용 시작]이 열려야 합니다. 서버 검사(2-1)가 최종 판단이므로 화면은 안내 역할입니다.
- 그 밖의 경우(RS가 아닌 시험 시작, 또는 RS가 아닌 시험 중인 사람)는 지금처럼 막습니다.

### 2-3-1. 시험번호 중복 검사 — 현재 없음 (R-6)

- 기획 SC-05의 "다른 시험장에서 이미 시험 중인 번호는 흐리게 막힘"이 지금 현황판 서버·화면에 구현돼 있지 않습니다. `start_etc_use`에 시험번호 검사가 없습니다.
- 구현할 때 단위는 **시험번호 + 시험항목**입니다. 기획서 문구는 시험번호 단위로 되어 있으므로 5장에 맞춰 함께 고칩니다.
  - ~~현황판 기록의 "항목"은 항목 줄(구역)입니다. 확인 필요: CE #1·CE #2처럼 같은 종류 항목을 같은 번호로 동시에 진행해도 되는지.~~
  - **확정 (2026-11-26)**: 항목 = 시험방법. 측정 행은 `MET_KEY`, 현황판 기록은 그 구역의 시험방법 매핑(`CHAMBER_ZONE_MET_TB`)입니다. 매핑이 하나라도 같으면 같은 항목입니다. 따라서 CE #1·CE #2는 둘 다 CE라서 같은 번호로 동시에 진행할 수 없고, BSD 구역(EFT·SURGE·VDIP)은 같은 번호의 EFT 측정과도 겹칩니다.
  - **RE는 이번 범위에서 뺍니다 (다음 단계)**: 구역 매핑은 대역 `RA`(RE Below)·`RB`(RE Above)인데 측정 행은 `RE1`·`RE2`·`RE3`이고, ERP는 규격에 따라 바꿉니다(9814: RE1·RE2→RA, RE3→RB / 그 외 RE1→RA, RE2→RB). 현황판 기록만으로는 RE1인지 RE2인지 알 수 없어 비교 방법을 정해야 합니다. 그때까지 `RA`·`RB`·`RE1~3`은 같은 항목 검사를 하지 않습니다.
- 현황판에서 고르는 시험번호는 자동화 로데이터 규격을 제외하므로(`RD_AUTO_STNDR`), ERP 측정 행과 같은 번호가 겹칠 일은 없습니다. 그래도 구현은 측정 행까지 함께 봅니다 (쿼리 하나로 같이 보고, 규격 설정이 바뀌어도 안전).
- 화면: 시작 팝업에서 시험번호와 항목을 고르면 같은 번호·같은 항목이 진행 중일 때 "같은 시험번호의 RS 시험이 RS #2에서 진행 중입니다"를 보여 주고 [사용 시작]을 막습니다. 서버도 거부합니다.
- 기록 수정에서 시험번호를 바꿀 때의 같은 항목 검사는 이번 범위에 넣지 않았습니다 (R-7은 R-1~R-5만).

## 3. 시험원 기준 — ERP와 현황판의 차이 (확인만)

| | 시험원 (`MEM_ID`) | 누른 사람 |
|---|---|---|
| ERP 측정 행 [시작] | [시작]을 누른 로그인 아이디 | 같음 |
| 현황판 [사용 시작] | 기술책임자·관리자가 고른 시험원 (본인이면 본인) | `REG_MEM_ID` |

- ERP는 "누른 사람 = 시험원"으로 확정했습니다. 기술책임자가 ERP에서 대신 [시작]을 누르면 기술책임자가 시험 중이 됩니다.
- 현황판은 기획 P-2 · SC-06에 따라 시험원을 고르는 구조이므로 **바꾸지 않습니다.** 검사는 양쪽 모두 `MEM_ID`로 하므로 규칙은 맞습니다.

| 3 | 화면이 구역의 RS 여부를 모름 | `/api/status`·`/api/zones`에 `rsYn`(+ `mets`) 추가, RS 구역이면 RS만 진행 중인 시험원도 고를 수 있게 안내와 함께 표시 |
| 4 | 시험원 현황이 동시 진행을 못 그림 | 겹치면 줄 추가 (2-5) |
| 5 | RS 구역에 다른 시험방법이 섞여 있는지 | 개발 DB 확인 결과 RS 구역 4곳 모두 매핑이 RS 하나뿐 (2026-11-26) |
| 6 | 동시 시작 경쟁 | **알려진 한계**. 1인 1시험·같은 항목 검사는 구역만 잠그고 시험원·시험번호는 잠그지 않는다. 같은 사람(또는 같은 번호)이 거의 같은 순간에 서로 다른 구역을 시작하면 둘 다 통과할 수 있다. ERP [시작]과 현황판 사이도 같다. 막으려면 양쪽이 같은 잠금(예: `GET_LOCK`)을 써야 해서 이번에는 하지 않는다 |
| 7 | 함께 바꿀 곳 | 이 문서 보완, 데모 서버(`OPS/tools/chamber_demo_server.py`)에 같은 규칙. 겹침 분석 SQL은 그대로 |
