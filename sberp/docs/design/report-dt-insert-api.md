# 성적서 발급정보 저장 일원화 — 프론트 전달

로데이터가 있는 시험도 성적서 발급일·발급번호·메모를 `/tst/insertReportDt.do` 로만 저장한다.
로데이터 기본정보 저장(`/raw/insert.do` 계열)은 더 이상 TEST_TB 발급정보를 저장하지 않는다.

## 1. 로데이터 기본정보 저장

- 요청의 `reportNo`, `reportDt`, `reportMemo` 는 **무시된다** (보내도 저장 안 됨).
- 화면의 발급정보 입력란은 기본정보 저장 버튼과 분리해서 아래 API 로 저장해야 한다.
- 저장된 발급일 이후로 시험시작일·시험종료일을 바꾸면 기존처럼 `성적서 발급일은 시험종료일 이후로만 입력할 수 있습니다.` 로 거부된다
  (기준이 요청값이 아니라 DB 에 저장된 그 시험의 발급일로 바뀜).

## 2. `POST /tst/insertReportDt.do`

요청 (JSON)

| 필드 | 필수 | 설명 |
|---|---|---|
| `testSeq` | O | 시험 고유번호. **재발행 시험은 그 재발행 시험의 testSeq** (원본 아님) |
| `reportDt` | O | `yyyy-MM-dd`. 빈 문자열이면 발급일 삭제(NULL) |
| `reportNo` | | 발급번호. **필드를 빼면 기존 값 유지**, 빈 문자열이면 빈 값으로 저장 |
| `reportMemo` | | 메모. 빼면 기존 값 유지 |

- `testItemSeq` 등 다른 필드는 보내지 않는다.
- `reportDt` 는 항상 그 값으로 덮어쓰므로, 발급번호만 바꿀 때도 현재 발급일을 같이 보낸다.

응답 `result` / `message`

| result | message | 상황 |
|---|---|---|
| true | `""` | 저장됨 |
| false | `권한이 없습니다` | 미로그인 |
| false | `필수입력값을 확인하세요` | testSeq 없음 |
| false | `성적서 발급일 형식을 확인하세요. (yyyy-MM-dd)` | 날짜 형식 오류 |
| false | `프로젝트가 완료되어 로데이터를 수정할 수 없습니다.` | 로데이터가 있는 시험이 수정 잠금 상태 |
| false | `성적서 발급일은 시험종료일 이후로만 입력할 수 있습니다.` | 로데이터가 있는 시험에서 발급일이 시험기간·측정기간보다 앞섬 |
| false | `데이터가 없습니다` 계열(NO_DATA) | 해당 testSeq 시험 없음 |
| false | `다시시도하세요` | 그 외 오류 |

로데이터가 없는 시험은 잠금·기간 검증 없이 저장된다 (기존과 동일).

## 3. 저장 순서

기본정보(시험기간)·측정일과 발급일이 서로를 검증하므로, 한 화면에서 둘 다 바꿀 때는

1. 발급일을 **늦추는** 경우: 발급일 먼저 → 기본정보/측정일
2. 발급일을 **당기는** 경우: 기본정보/측정일 먼저 → 발급일

순서가 틀리면 앞 요청이 이전 값 기준으로 거부될 수 있다. 앞 요청이 실패하면 뒤 요청은 보내지 않는다.

## 4. 재발행 시험

로데이터 화면의 발급정보 목록(`reportList`)은 원본·재발행 시험별로 행이 있다. 행마다 그 행의 `testSeq` 로 따로 호출한다.
검증은 모두 원본 시험의 로데이터(공유) 시험기간·측정기간 기준이다.
