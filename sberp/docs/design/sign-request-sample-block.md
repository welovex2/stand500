# 시료 없는 시험신청(서명요청) 차단 — 프론트 전달

반입된 시료가 없으면 `/sbk/signRequest.do`(서명요청하기)를 서버가 처리하지 않고 거부한다.
지금 화면은 시료가 없을 때 경고만 띄우고 진행시키지만, 이제는 진행해도 서버에서 막힌다.

## 1. 차단 기준

| 경우 | 결과 |
|---|---|
| 현장시험 신청서 (`testPlaceOutYn = 1`) | 시료 확인 없이 **통과** |
| 재발행 신청서 (신청서번호에 `-1`, `-2` … 리비전이 붙은 경우) | 시료 확인 없이 **통과** |
| 그 외 | 반출되지 않고 남은 시료(구분 = 시료)가 1개 이상 있어야 통과 |

- 부속품 등 시료가 아닌 구분은 세지 않는다.
- 반입했다가 이미 반출된 시료만 있으면 **막힌다**.
- 삭제된 반입 건은 세지 않는다.

## 2. `POST /sbk/signRequest.do`

요청은 기존과 같다 (`testItemSeq`, `revId`, `sendType`, `estCmpDt`).

응답 `result` / `message`

| result | message | 상황 |
|---|---|---|
| true | `""` | 서명요청 처리됨 |
| false | `반입된 시료가 없어 시험신청을 할 수 없습니다.` | 시료 없음 (위 기준) |
| false | `데이터가 없습니다` | testItemSeq 에 해당하는 시험항목 없음(삭제 포함) |
| false | `권한이 없습니다` | 미로그인 |

## 3. 화면 처리

- 지금의 시료 경고는 "확인 후 진행" 형태가 아니라 **진행 불가 알림**으로 바꾼다.
  또는 경고 없이 바로 호출하고 `result = false` 이면 `message` 를 그대로 띄운다.
- 화면에서 미리 판단한다면 현장시험·재발행 신청서에는 경고를 띄우지 않아야 한다 (서버는 통과시킴).
- 화면의 판단과 서버의 판단이 다를 수 있으므로, 어느 쪽이든 응답의 `result` / `message` 는 반드시 처리한다.

## 4. 영향 없는 API

- `/sbk/cmpDt/update.do`(요청완료일 변경)는 같은 저장 로직을 쓰지만 **시료 확인을 하지 않는다**. 기존과 동일.
- `/tst/makeTest.do`(시험 생성)도 변경 없음.
