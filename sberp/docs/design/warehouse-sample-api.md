# 창고·시료 API

기준은 `창고_시료관리_업무규칙_정의서` v2 (2026-09-29, 모바일 절은 비움)이다.
시험은 신청서에 붙고, 시료 한 건에 시험을 매다는 API는 두지 않는다.

## 단어

| 말 | 의미 |
| --- | --- |
| 시료 반입 | PC에서 시료를 등록한다. 회사 안으로 들이는 일이다. |
| 보관 | 구역 QR을 찍어 그 칸에 둔다. |
| 꺼내기 | 구역을 비운다. 이번 코드에는 별도 버튼이 없고, 다른 구역 QR을 찍으면 위치가 바뀐다. |
| 반출 | 회사 밖으로 나간다. 한 번이면 끝이고, 되돌리지 않는다. 다시 오면 새 시료번호다. |
| 사용 중지 | 창고·구역을 지우는 일이 아니다. 되살리지 않고, 기본 목록에서는 숨긴다. |

창고 사이 이동에 `반입`/`반출`을 쓰지 않는다. 반출대기는 공정 단계가 아니라, 프로젝트 완료일로부터의 경과일 표시다. 이번 API에는 그 계산이 없다.

## 있는 API

### 창고 `/cnf/str`

| 메서드 | 경로 | 하는 일 |
| --- | --- | --- |
| GET | `/list.do` | 사용 중인 창고. `includeStopped=Y` 이면 중지된 창고도 포함한다. `mngDeptName`은 관리자 부서. `zoneCnt`는 사용 중인 구역, `stopZoneCnt`는 중지된 구역이다. |
| GET | `/{strSeq}/detail.do` | 창고와 구역. 중지된 창고도 연다. 구역 목록에는 중지된 구역이 남는다. |
| POST | `/insert.do` | 등록. 창고는 `strSeq`(STR_SEQ)만 갖는다. 창고명·관리자 필수. 사용 중인 창고끼리는 이름이 겹치면 안 된다. |
| POST | `/update.do` | 수정. 중지된 창고는 거절한다. |
| POST | `/stop.do` | 사용 중지. 그 창고 시료가 0건일 때만. 속한 구역도 같이 중지한다. 되살리는 API는 없다. |
| POST | `/zone/insert.do` | 구역 하나 추가. `zoneName`은 그 창고의 사용 중인 구역끼리 겹치면 안 된다. |
| POST | `/zone/insertRange.do` | 접두어와 번호로 한 번에 추가. `가` + 1~12 → `가-01`~`가-12`. 최대 50개. 이미 쓰는 이름은 뺀다. `zoneDesc`를 적으면 만든 구역에 같이 붙는다. |
| POST | `/zone/update.do` | 넣은 값만 수정. 구역명·설명은 용도를 건드리지 않는다. `zoneSeq`와 `useCode`만 넣으면 용도만 저장한다. 시료상태 컬럼이 없어 보관 시료 상태 변경은 아직 하지 않는다. 중지된 구역은 거절한다. |
| POST | `/zone/stop.do` | 구역 사용 중지. body 는 `zoneSeq` 만. 시료가 남아 있으면 거절한다. |

창고 번호는 `strSeq`(STR_TB.STR_SEQ)다. 구역 번호 `zoneSeq`는 ZONE_TB 전체 자동 번호이고, 창고마다 1부터 다시 세지 않는다.

### 시료 `/sam`

| 메서드 | 경로 | 하는 일 |
| --- | --- | --- |
| POST | `/insert.do` | PC 시료 반입. 사진 첨부는 기존과 같다. |
| GET | `/list.do` | 시료 목록. |
| GET | `/{sbkId}/detail.do` | 신청서 단위 시료. |
| GET | `/item/{imSubId}/detail.do` | 라벨 한 건. 위치와 이동 이력. 예: `SB26-G0030-M01`. |
| POST | `/loc/scan.do` | 구역 QR과 시료 라벨 1~N건. 위치만 남긴다. 시험 번호는 받지 않는다. |

같은 신청서의 다른 시료가 다른 칸에 있어도 경고하지 않는다. 시료는 따로 움직인다.

위치 스캔이 사용 중지된 창고·구역을 치면 `사용 중지된 구역입니다. 라벨을 떼 주세요.` 를 돌려준다.

## 없는 API

- `/sam/occupy/claim.do`, `/sam/occupy/release.do` — 시료에 시험부를 묶던 시험용 API. 제거했다.
- 시료와 시험을 표로 잇는 저장 API. 신청서의 시험 목록은 기존 시험 API가 갖고, 시료 상세는 그 목록을 새로 저장하지 않는다.
- 폰에서 시험 상태를 바꾸는 API. 상태 변경은 기존 시험 리스트와 같다.
- 구역 용도(일반/인수요청/장기), 용도를 바꿀 때 시료 상태를 같이 바꾸는 일.
- 시료 상태 7종(보유, 보관, 보관(인수요청), 보관(장기), 외출, 반출, 폐기) 전용 전이 API.
- 인수요청 경과일, 반출대기 일수, 반입 사진 필수 검사.

`IM_SUB_TB`의 점유 컬럼과 `IM_SUB_OCCUPY_TB`는 코드에서 더 이상 읽거나 쓰지 않는다. 컬럼 삭제는 이번 범위에 넣지 않았다.

## 이번 코드가 규칙과 다른 점

- 구역 용도 컬럼이 없다.
- 시료 `procState`는 예전 `IN/TEST/WAIT/KEEP/OUT` 이다. 규칙의 7상태와 같지 않다.
- 창고는 `strSeq`만 쓴다. 화면용 창고코드는 없다.
- QR 뒤자리는 사람이 읽는 구역코드다. 규칙의 「코드는 숨기고 이름만 보여 준다」와 인쇄 위치가 다르다.
- 창고 `memo` 컬럼은 남아 있다. 규칙의 설명 필드는 아니고, 위치(`whLoc`)가 그 역할이다.
- 관리자는 필수이고, 재직 사용자만 고르는 검사는 아직 없다.
