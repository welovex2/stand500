# 시료번호 전환 — 옛 번호와 새 번호를 같이 쓰는 방법

- 근거: `창고_독자번호_v12.html` (2026-10-14) · 현재 코드 · 운영 덤프 `target/db_20260608.sql`
- 상태: **분석.** 확정된 것은 번호 체계뿐이고, 시료 기획이 끝나면 다시 본다
- 같이 볼 문서: `시료상태_설계.md` — 이 전환으로 바뀌는 곳에 `[번호 전환]` 표시를 달았다

## 0. 결론

**새 시료는 `IM_SUB_TB` 에 한 줄씩 넣되 `IM_TB` 는 거치지 않는다. 번호는 별도 채번 테이블에서 받고, 신청서 · 시험과는 연결 테이블로 잇는다.**

- `IM_SUB_TB.IM_ID` = `'S26'`(해), `IM_SUB_SEQ` = 그해 순번 1, 2, 3 … 으로 넣는다. 화면 번호는 `CONCAT(IM_ID, '-', LPAD(IM_SUB_SEQ, 5, '0'))` = `S26-00001` (2026-10-19 사용자 제안)
- 옛 조회는 모두 `IM_TB` → `CONCAT('IM', …)` 로 `IM_SUB_TB` 를 찾는다. `S…` 로 시작하는 새 줄은 어떤 옛 조회에도 걸리지 않으므로 **옛 데이터는 지금과 똑같이 나온다** (5장)
- 창고 코드(`CURRENT_ZONE_SEQ` · `IM_SUB_LOC_TB` · 구역 건수)와 `시료상태_설계.md` 의 칼럼 · 이력 키(`IM_ID` + `IM_SUB_SEQ`)를 **그대로 쓸 수 있다**

`IM_TB` 를 번호의 기준으로 쓰는 안(3장 B)은 운영 데이터로 보면 1만 번째에서 옛 시료와 키가 겹친다. 쓰지 않는다.

기획(v10 · v11)과도 맞는다.

- 옛 시료 리스트는 손대지 않고 기록으로만 둔다
- 새 시료 리스트는 정한 날부터 새로 시작한다
- 기존 시료는 누가 손댈 때 새 QR을 뽑아 붙이고, 그 순간부터 그냥 새 시료다(반입일 = QR 뽑은 날)
- 옛 번호는 새 리스트에 보이지 않고 검색되지도 않는다

## 1. 무엇이 바뀌나

| | 옛 번호 | 새 번호 |
|---|---|---|
| 형식 | `SB26-G1194-M01` | `S26-00001` |
| 생기는 때 | 신청서 화면에서 반입 등록 | PC **시료 QR 출력** — 출력이 곧 반입 |
| 신청서 · 시험 | 번호 안에 신청서가 들어 있다. 1:1 | 번호에 없다. **연결**로 잇는다. 한 시료에 여럿 |
| 순번 | 신청서 안에서 `01` 부터 | 해마다 `00001` 부터. 본품 · 부품 · 세트가 한 순번 |
| 저장 | 저장하지 않는다. 조회 때 `SBK_ID + '-M' + LPAD(IM_SUB_SEQ,2,0)` 로 만든다 | 저장한다 |
| 신청서 없는 시료 | 있을 수 없다 | 있다 — 「신청서 미연결」 · 「신청서 없음」 |
| 업체 · 제품 · 모델 | 신청서(`JOB_TB`) 값 | 시료가 갖는다. 첫 연결 때 신청서 값으로 채운다 |
| 구분 | `1` 본품 · `2` 구성품 | 본품 · 부품 · 세트 |

옛 번호의 신청서 부분은 `SB25-M0071-1` 처럼 유형 글자가 `G` 말고도 있고 개정 번호가 붙기도 한다(덤프 확인). 옛 번호 판별 정규식은 지금 `SamItemIdSupport` 것을 그대로 쓰면 된다.

## 3. 방안 비교

### A. 완전히 새 테이블(`SMP_TB` 등) — 가능하지만 일이 많다

- 옛 테이블과 경계가 가장 분명하다
- 창고 코드(위치 · 구역 건수 · 스캔)와 시료상태 설계를 모두 새 키로 옮겨야 한다

### B. `IM_TB` 를 번호 기준으로 — 쓰지 않는다

새 시료마다 `IM_TB` 에 한 줄을 넣고 `IM_SEQ` 를 번호로 쓰는 안이다. 문제가 셋 있다.

1. **1만 번째에서 옛 시료와 키가 겹친다.** `IM_SUB_TB.IM_ID` 는 `varchar(10)` 이고 `FN_GET_SEQSTRING` · 모든 조인이 `LPAD(IM_SEQ, 4, 0)` 이다. MySQL `LPAD` 는 길면 잘라서 `LPAD(10000,4,0)` = `'1000'` 이 된다. 1만 번째 시료가 `IM26-G1000` 으로 저장되어 옛 신청서의 시료에 붙거나 PK 가 충돌한다. 한 해 수량이 이미 6~7천이고 부품까지 낱개 번호를 받으면 넘을 수 있다. 고치려면 칼럼 길이 · 함수 · 옛 조인 열 곳 이상을 모두 바꿔야 해서 「옛 것은 손대지 않는다」가 깨진다
2. **번호가 1부터 시작하지 않는다.** `IM_SEQ` 는 신청서 반입 등록과 같은 순번이라 2026년은 이미 2,187(6월 기준) 위에서 이어진다. 전환일 전까지는 옛 반입 등록과 번갈아 늘어난다
3. **`IM_TB` 의 뜻이 둘로 갈린다.** 옛 줄은 「신청서 하나」, 새 줄은 「시료 하나」. `SBK_ID` 는 `NOT NULL` 이고 PK 에 들어 있어 빈 값으로 두려면 PK 를 바꿔야 한다. 연결이 여럿이라 `SBK_ID` 칸에 담을 수도 없다. `IM_TOTAL_V` 는 새 줄을 `SBK_ID` 빈 값 하나로 묶은 쓸모없는 줄을 만든다

### C. `IM_SUB_TB` 에 직접 넣고 `IM_TB` 는 거치지 않는다 — **추천**

| | |
|---|---|
| 시료 줄 | `IM_SUB_TB` 한 줄. `IM_ID = 'S26'` · `IM_SUB_SEQ` = 그해 순번 |
| 번호 | `IM_SUB_SEQ` 가 곧 순번이다 (4장 채번) |
| 신청서 · 시험 | 연결 테이블 (4장) |
| 옛 조회 | 모두 `IM_TB` 를 거쳐 `IM…` 로 찾으므로 새 줄을 보지 못한다 → 그대로 |
| 창고 · 시료상태 | 키가 `IM_ID` + `IM_SUB_SEQ` 그대로 → 옮길 것이 없다 |

「옛 구조를 그대로 가야 하나」에 대한 답: **번호와 연결은 새로, 시료 한 줄을 담는 칸(`IM_SUB_TB`)은 그대로.** `IM_TB` 의 「신청서 1:1」 구조는 한 시료에 여러 신청서 · 시험이 붙는 새 규칙을 담지 못하므로 거치지 않는다.

조심할 점 — 앞으로 `IM_SUB_TB` 를 `IM_TB` 없이 직접 읽는 조회는 옛 줄 · 새 줄이 섞인다는 것을 알고 써야 한다. 구분은 `IM_ID LIKE 'S%'` 로 충분하다.

### D. 옛 시료를 새 번호로 일괄 이관 — 제외

기획이 하지 않기로 했다(v11).

### `IM_SUB_TB` 칼럼

|---|---|
| `SNM` | 부품 이름 · S/N |
| `CMPY_NAME` · `PRDCT_NAME` · `MODEL_NAME` | 시료가 갖는 값. 첫 연결 때 신청서 값으로 채운다 |
| `NO_APP_YN` | `Y` 연결할 신청서가 ERP 에 없음(「신청서 없음」) |
| `SST_*` · `PICK_MEMO` · `OUT_DAYS` | `시료상태_설계.md` 2장 |
| `OLD_IM_ID` · `OLD_IM_SUB_SEQ` | 옛 시료에 새 QR을 붙였을 때 출처. 화면에는 안 보인다 (7장 ③) |

옛 줄은 모두 `NULL` 이다. 옛 조회는 이 칼럼을 읽지 않는다. `CARRY_IN_DATE` 는 `date` 라 QR 출력 시각을 담지 못한다 — 날짜면 충분한지, 시각 칼럼을 따로 둘지 정한다.

### 연결 — `IM_SUB_LINK_TB`

신청서로 이을지 시험으로 이을지 아직 정하지 않았으므로 둘 다 담을 수 있게 둔다.

| 칼럼 | 뜻 |
|---|---|
| `IM_SUB_LINK_SEQ` | PK |
| `IM_ID` · `IM_SUB_SEQ` | 시료 (새 줄만) |
| `SBK_ID` | 연결한 신청서 |
| `TEST_SEQ` | NULL 가능. 시험으로 이을 때 |
| `LINK_WAY` | `P` 폰 [신청서 연결] · `S` ERP 신청서 화면 |
| `INS_MEM_ID` · `INS_DT` · `STATE` | 연결한 사람 · 때 · 끊음(`D`) |

시험으로 잇기로 해도 신청서는 시험에서 거슬러 찾을 수 있지만, 목록 · 검색이 늘 신청서 기준이라 `SBK_ID` 를 같이 적어 두는 편이 조회가 싸다.

### 채번 — `IM_ID` = 해, `IM_SUB_SEQ` = 순번

`IM_ID` 를 해(`'S26'`)로 두고 `IM_SUB_SEQ` 를 그해 순번으로 쓴다. 지금 `insertSub` 의 `MAX(IM_SUB_SEQ)+1 WHERE IM_ID = ?` 방식이 그대로 통한다.

```sql
SELECT IFNULL(MAX(IM_SUB_SEQ), 0) + 1 FROM IM_SUB_TB WHERE IM_ID = 'S26';   -- STATE 'D' 도 포함해서 센다
INSERT INTO IM_SUB_TB (IM_ID, IM_SUB_SEQ, …) VALUES ('S26', ?, …);
-- 화면 번호 = CONCAT(IM_ID, '-', LPAD(IM_SUB_SEQ, 5, '0'))  →  S26-00001
```

- **채번 테이블이 따로 필요 없다.** 두 사람이 동시에 출력해 같은 순번을 읽어도 PK `(IM_ID, IM_SUB_SEQ)` 때문에 뒤엣사람 INSERT 가 키 중복으로 실패한다. 잘못된 번호가 저장되지는 않는다. 실패하면 서버가 한 번 더 읽어 다시 넣는다. QR 은 INSERT 가 끝난 뒤에 찍으므로 종이에 틀린 번호가 나가지 않는다
- **해가 바뀌면 `IM_ID` 가 `'S27'` 이 되고 순번은 1 부터 다시 시작한다.** 기획의 「해마다 00001 부터」와 같다
- 지운 시료(`STATE = 'D'`)도 `MAX` 에 넣어 센다. 번호를 다시 쓰지 않기 위해서다
- 폰 · PC 에서 번호를 받으면 `S26-00001` → `IM_ID = 'S26'`, `IM_SUB_SEQ = 1` 로 쪼개 PK 로 바로 찾는다
- 옛 `IM_ID` 는 모두 `IM…` 이라 `'S26'` 과 겹치지 않는다. 옛 쿼리(`insertSub` · `subList` 등)는 `IM_ID = 'IM…'` 로만 찾으므로 새 줄을 건드리지 않는다
- `IM_ID` 를 `'SB26'` 으로 해도 동작은 같다. 다만 `SB26-…` 은 신청서 번호의 앞머리라 사람이 볼 때 헷갈리고, 화면 번호 `S26-00001` 과도 앞머리가 달라진다. **`'S26'` 을 권한다**
- 다섯 자리면 한 해 99,999개로 넉넉하다 (2025년 수량 6,812)

## 4-1. 한 시료를 여러 신청서에 쓰는 흐름

업무: 시료가 들어와 **1번 신청서**의 시험에 쓰이고 창고에 보관된다. 나중에 **23번 신청서**가 들어오면 창고에 있던 그 시료를 꺼내 다시 쓴다.

시료 줄은 처음부터 끝까지 `IM_SUB_TB` 의 **한 줄(`S26-00001`)** 이다. 신청서가 바뀌어도 시료 줄은 새로 생기지 않고, 연결 테이블에 줄이 하나 더 붙을 뿐이다.

| 순서 | 일 | `IM_SUB_TB` (`S26` · 1) | `IM_SUB_LINK_TB` | 상태 · 이력 |
|---|---|---|---|---|
| 1 | 시료 도착 · PC 에서 QR 출력 | 줄 생김. 업체 · 제품 빈칸 | — | 보유 · 「신청서 미연결」 |
| 2 | 폰 [신청서 연결] 로 1번 신청서에 연결 | 업체 · 제품 · 모델을 1번 신청서 값으로 채움 | `S26`·1 ↔ SB26-G0001 | 이력: 신청서 연결 |
| 3 | 1번 신청서 시험 진행 | — | — | 시험은 1번 신청서에 붙어 있다 |
| 4 | 시험 끝 · 창고 구역 QR 스캔 | `CURRENT_ZONE_SEQ` 설정 | — | 보관. 1번 신청서 시험이 모두 끝났으면 **반출대기 시작** |
| 5 | 23번 신청서 접수 · 그 시료를 쓰기로 함 | 변화 없음 | `S26`·1 ↔ SB26-G0023 **추가** (1번 연결은 그대로) | 이력: 신청서 연결. 23번에 끝나지 않은 시험이 있으므로 **반출대기 멈춤** |
| 6 | 창고에서 꺼냄 | `CURRENT_ZONE_SEQ` 지움 | — | 보유 |
| 7 | 23번 시험 끝 · 다시 보관 | 구역 설정 | — | 보관. 반출대기는 **23번 완료일부터** 다시 센다 |
| 8 | 반출 | 반출 정보 | 두 연결 모두 남음 | 반출. 이후 새 연결 불가 |

### 연결을 하는 곳

- **폰 [신청서 연결]** — 시료 QR 을 찍고 신청서를 고른다
- **ERP 신청서 화면 「새 시료번호 영역」** — 23번 신청서 화면에서 `S26-00001` 을 넣거나 PC 스캐너로 QR 을 찍는다. 다른 신청서에 연결된 시료도 연결할 수 있다
- 반출 · 폐기된 시료는 연결할 수 없다. 업체가 다르면 경고만 하고 「그래도 연결」을 받는다(목업)

### 연결이 여럿일 때 화면이 읽는 값

| 화면 값 | 읽는 법 |
|---|---|
| 시료 리스트 「접수번호」 | 가장 최근 연결(`INS_DT` 최신) + 「외 N」 |
| 업체 · 제품 · 모델 | 시료가 갖는 값(`IM_SUB_TB`). 첫 연결 때 채운 값이 남는다 |
| 컨설팅 · 담당자 · 신청접수일 | 가장 최근 연결 신청서 값 |
| 시료 상세 「시험」 | 연결된 신청서 모두의 시험을 신청서별로 묶어 |
| 반출대기 | 연결된 신청서 중 하나라도 끝나지 않은 시험이 있으면 「—」. 모두 끝났으면 가장 늦은 완료일부터 |
| 신청서 화면 「새 시료번호 영역」 | 그 신청서에 연결된 시료. 다른 신청서에도 연결돼 있으면 「다른 신청서도」 |

### 1번 연결을 끊지 않는 이유

1번 신청서의 시험 · 성적서 · 사진은 그 시료로 한 일이다. 연결을 지우면 1번 신청서 화면에서 「어떤 시료로 시험했는지」가 사라진다. 그래서 연결은 쌓기만 하고, 잘못 연결했을 때만 `STATE = 'D'` 로 끊는다.

### 시험으로 이을 경우

연결 단위를 시험(`TEST_SEQ`)으로 정하면 5 번에서 23번 신청서의 시험마다 한 줄씩 붙는다. 흐름은 같고, 「이 시료를 어느 시험에 썼는지」까지 남는 대신 연결할 때 시험을 골라야 한다. 목업(2026-09-29)은 시험 단위 연결을 뺐다 — 「시험은 신청서에 붙는다」.

## 5. 옛 데이터가 그대로 나오는지 — 조회별 점검 (C안 기준)

새 줄은 `IM_TB` 에 없으므로, `IM_TB` 를 거치는 조회에는 들어오지 않는다.

| 조회 | `IM_SUB_TB` 를 찾는 길 | 옛 데이터 | 전환 뒤 새 신청서 |
|---|---|---|---|
| 옛 시료 리스트 `samMapper.selectList` · `selectListCnt` | `IM_TB` INNER JOIN · `SBK_TB` INNER JOIN | 그대로 | 나오지 않음 — 의도대로 |
| 신청서 기존 시료 영역 `subList` · `insertSub` · `updateSub` · `deleteSub` | `IM_ID = 'IM…'` | 그대로 | — |
| `selectSubBySbkIdAndSubSeq` (옛 번호 상세 · 위치 스캔) | `IM_TB.SBK_ID` | 그대로 | 새 번호용 조회를 따로 둔다 |
| `IM_TOTAL_V` → `SBK_V.carryInDt` | `IM_TB` LEFT JOIN | 그대로 | **반입일 · 수량이 빈다** ⚠ |
| `sbkMapper` 신청서 목록 `inCnt` · `outCnt` | `IM_TB` 묶음 | 그대로 | **0 으로 나온다** ⚠ |
| `tstMapper` 시험 리스트 반입일 (3곳) | `IM_TB` 묶음 | 그대로 | **빈다** ⚠ |
| `legMapper` (2곳) | `IM_TOTAL_V` | 그대로 | **빈다** ⚠ |
| `strMapper` 창고 · 구역 보관 건수 (4곳) | `IM_SUB_TB` 직접 · `CURRENT_ZONE_SEQ` | 옛 시료는 구역 값이 없어 0 | 새 시료가 세진다 — 의도대로 |
| `IM_TB.update` (`substring(imId,7,4)`) | `IM_TB` | 그대로 | — |

정리하면 **옛 데이터는 깨지지 않는다.** 대신 전환 뒤에 들어온 신청서는 신청서 목록 · 시험 리스트의 반입일 · 수량 칸이 빈다. 이 칸들은 「`IM_TB` 묶음 + 연결 테이블로 이은 새 시료」를 합쳐 읽도록 바꿔야 한다(7장 ①). 가장 손이 덜 가는 곳은 `IM_TOTAL_V` 하나를 고치는 것이다 — `SBK_V` 와 `legMapper` 가 이 뷰를 읽는다. `sbkMapper` · `tstMapper` 는 같은 묶음을 쿼리 안에 직접 쓰고 있어 따로 고친다.

같은 신청서에 옛 시료와 새 시료가 함께 있을 수도 있다(전환일 전후로 걸친 신청서, 옛 시료에 새 QR을 붙인 경우). 합칠 때 같은 물건을 두 번 세지 않으려면 7장 ③ 의 출처 칼럼이 필요하다.

## 6. 두 번호가 만나는 곳

| 곳 | 처리 |
|---|---|
| **폰 스캔** | 정규식으로 가른다. `^S\d{2}-\d{5}$` 는 새 번호. `SamItemIdSupport` 의 옛 정규식에 맞으면 「옛 QR입니다 · 새 QR을 출력해 붙이세요」. 접두가 `S2` · `SB` 라 겹치지 않는다 |
| 시료 리스트 · 시료 상세 | 새 줄(`IM_ID LIKE 'S%'`)만 읽는다 — `IM…` 과 앞 글자가 달라 이것으로 충분하다. 옛 번호 검색 없음 |
| 창고 | 새 줄만 구역에 들어간다. 옛 시료를 창고에 넣으려면 새 QR 부터 |
| **신청서 화면** | 두 영역. 기존 영역 = `IM_TB` 경유 (반출 입력은 남기고 새 반입 등록만 막는다). 새 영역 = `IM_SUB_LINK_TB` |
| 사진 폴더 | 옛 = 신청서 폴더. 새 = 시료 기준(기획 미결) |
| 전환 시작일 | 그날부터 신청서 화면의 새 반입 등록을 막고 QR 출력을 연다 |

## 8. 확정이 필요한 것

### ① 신청서 · 시험 쪽 집계에 새 시료를 어떻게 셀지

5장의 ⚠ 칸들. 한 시료가 여러 신청서에 이어지면 신청서마다 한 번씩 세어진다. 시험 리스트 반입일은 연결된 본품이 여럿이면 가장 이른 날로 할지. 서명요청 조건(목업은 「연결된 시료가 1개 이상」).

### ② `SAM_ZONE_LOC.sql` 을 운영 DB 에 적용했는가

적용 전이면 지금 구조로 그대로 적용하면 된다. 옛 `IM_SUB_LOC_TB` 는 0건이라 DROP 해도 잃는 것이 없다(6월 기준 — 적용 직전에 다시 센다). 같은 날 옛 `SB…-M01` QR 이 인쇄 · 부착된 적이 있는지도 함께 확인한다. 없으면 폰의 「옛 QR」 안내는 필요 없다.

### ③ 출처 칼럼 `OLD_IM_ID` 를 둘지

기획은 「옛 리스트의 미반출 건은 정리되지 않고 그대로 남는다」고 받아들였다. 하지만 5장의 집계를 합칠 때 같은 물건이 옛 줄 · 새 줄로 두 번 세어지는 것을 막으려면 이 값이 있어야 한다. 새 QR을 붙일 때 옛 시료를 고르는 단계가 하나 는다.

### ④ 신청서로 이을지 시험으로 이을지

연결 테이블은 둘 다 담게 잡았다. 정해지면 쓰지 않는 칼럼을 뺀다.
