## 동작 순서 요약

- 새 화면 : 빈 행에서 측정장소 선택 → [시작] → 온습도·서명 입력 [저장] → [종료] → [추가]로 다음 회차. 진행 중 행은 [중단] 가능. 종료된 행은 기책 [수정]·[삭제].
- 기존 화면 : 측정일 칸 + 로데이터 [저장]. 행이 없으면 저장 때 새 행(MIG_YN=2), 있으면 그 행 수정.
- [시작]·[종료]·기책 [수정] 때 서버 검사 : 챔버 대역 → 챔버 사용 중 → 1인 1시험 → 발급일 → 교정일. [종료]·[수정]은 시간 겹침도 확인.

## 미결

1. 프론트 `MANAGER_LIST_ONLY = true` (테스트용) — 서버 canRevEdit·canDelete를 안 보고, 진행 중 행 [수정]이 안 보임 → V-11·P-02 확인 불가. 운영 전 false
2. TEL 메뉴 링크 `dt` 누락 → `dt=null`, 성적서 구양식 (raw_basic_tel.js) — T-04
3. 시험원 na·da 서명 미등록 — [서명]이 비어 [종료] 불가. 두 사람이 [종료]까지 하는 케이스는 서명 등록 후 가능
4. 기책 [수정] 화면에서 이름 칸 읽기 전용·[서명] 버튼 없음 — update.do 는 memName·atchFileId 변경을 받음. 화면에서 막은 게 의도인지 확인 (프론트)
5. 로데이터 신규 저장 후 이동 주소와 메뉴 링크에 `dt=null` (raw_update.html 전체, TEL 외 화면도). 성적서 출력 양식 판단에 쓰는 화면이 있는지 확인 (프론트)
6. 미래 일시 거부 메시지가 일반 문구 "시작·종료 일시를 확인하세요" (update.do, 기존 화면 저장)
7. RS #3 사용 중이면 "RE (10m) > RS (#3실)"도 사용 중으로 표시 — 같은 방이라 의도된 것인지 확인
8. V-04·B-05(RS끼리 동시 진행) 미확인 — RS #2·#4를 다른 테스터가 쓰고 있고, RS #3과 RE (10m)/RS (#3실)은 함께 사용 중으로 묶여 빈 RS 구역이 하나뿐. RS↔비RS 거부는 ERP·현황판 양쪽 확인됨
9. 기존 화면에 기책 [삭제] 버튼 없음 (L-09) — 서버는 canDelete=true, delete.do 정상. 측정 기록 영역을 통째로 숨겨서 버튼도 안 보임 (프론트)
10. L-07(발급일 이후 측정일) 미확인 — 기존 시험번호 2건 모두 성적서 발급일 없음. 발급일 있는 기존 시험번호 필요
11. B-07 현황판 쪽(기록 수정으로 ERP 측정과 겹침) 미확인 — 현황판 기록 수정은 관리자(P01·P02)만 가능, 받은 계정(시험원 P15, 기책 P04)으로 불가. ERP 쪽(update.do 가 현황판 기록과 겹치면 거부)은 확인됨
